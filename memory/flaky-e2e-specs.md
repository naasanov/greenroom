Quarantine mechanism (#137): the tests listed in `apps/e2e/quarantine.json` are excluded from the blocking `e2e (...)` shard jobs and run in the non-blocking `e2e quarantine (desktop|mobile)` jobs (`continue-on-error`, one retry, report artifact `playwright-quarantine-report-<project>`). A red quarantine check is not a merge blocker and is not a fix attempt. Remove an entry from the JSON once its cause is fixed and the quarantine check has been green on several runs.
- Promoted from the mobile quarantine to the blocking jobs after 13 green WebKit quarantine runs (no retries), with `quarantine.json` now empty (#137). `media-upload.spec.ts` wake lock and EXIF: the tray tile leaves as soon as the file reaches the gallery, so asserting `data-status=done` raced (#77, #128); the specs wait on the stored bytes and the tile leaving. `agenda-drawer.spec.ts` hand-off: a transient `data-exiting` assertion raced the exit animation (#127); do not reintroduce a check on the exit window. Under heavy CPU steal on the factory box (20x desktop repeats) these specs only fail on the shared 5s waits in `openGallery` and the tile leaving, which every media spec has.
- Desktop `files-import` gigs root step and `setlist-gig` drag reorder were promoted back to the blocking jobs (#137). The gigs root step never failed in CI after its heading wait landed (#89); the earlier failures read `driveStatus` before that wait existed. The drag flaked because the spec dropped at `row.bottom - 8`, which at 1280x800 sits inside the drawer body's bottom 5% auto-scroll band (#133): once the pointer dwelled over 200ms the drawer scrolled mid-drag and the row landed one slot low. The spec now centres the list first and asserts the drop point is outside the edge bands.

**Why:** a one-line CSS change failed CI twice on these, which cost two fix attempts on a correct diff.
**How to apply:** when a spec reads API state right after a UI click, first wait for the UI signal produced by that mutation's success. A failure in the blocking jobs is real: rerun once only if the failing spec is not in `quarantine.json` and the diff does not touch its area. Quarantined specs report in the `e2e quarantine` check only. To promote one, remove it from `apps/e2e/quarantine.json` once green on several runs. Never add retries, skips or weaker assertions to make them pass inside an unrelated unit. A structural fix is tracked as a `[factory]` issue.
